A complete teardown of **Chu Chu Rocket**, build 1.18 LITE (Reservoir Gods, 2002), from `CHUCHU.TOS` and `CHUCHU.LNK`. The game is rebuilt **for the Atari ST**. This is not a port: the code stays 68000, as a complete assembly source.

- `src/chuchu.s` (39,000 lines, Motorola/Devpac syntax, vasm assembler) gives back **the executable identical to the byte**. Every one of its 907 functions is named and commented in English.
- `assets/` holds the 178 data files, with the graphics as editable indexed PNGs. Imported back unchanged, they give **`CHUCHU.LNK` identical to the byte**.
- The source can be edited: the shift test (16 bytes of padding inserted before 876 functions, +14 KB) runs in Hatari exactly like the original.
- `src/settings.s` holds the rules of the game (speeds, scores, times...) as plain values.

## Building

Requirements: Python 3 with Pillow, and [vasm](http://sun.hasenbraten.de/vasm/) built for the Motorola syntax (`make CPU=m68k SYNTAX=mot`), i.e. `vasmm68k_mot` in the PATH.

```
python build.py --check          # out/CHUCHU.TOS + out/CHUCHU.LNK, compared with the originals
python build.py --reforged       # REFERENCE VERSION: optimised + fixed + title banner
python build.py -D OPTIM         # optimisations only (see below)
python build.py -D SKIP_INTRO    # variant: no Atari intro and no logos
python tools/verify.py           # all the checks (see METHODOLOGY.md)
```

Assembly options, which can be combined (`-D OPTIM -D SKIP_INTRO`). With no option, you get the exact original binary:

| Option | Effect |
|---|---|
| `OPTIM` | Enables every `OPT_*` optimisation. |
| `OPT_MIXER` | The DMA audio mixer (STE) no longer mixes silence. |
| `OPT_TIME` | Clock duration conversions without `_lmul`/`_uldiv`. |
| `OPT_BLIT` | Restores the background under the sprites with the blitter, when there is one (STE, Mega STe, TT, Falcon). Consecutive tiles are copied in a single operation. |
| `NO_BLIT` | Removes `OPT_BLIT` from `OPTIM`, for comparisons on real hardware. |
| `FIX_MOUSE` | Fixes a bug of the original game: the mouse stayed disabled under GEM after a game played without a mouse player. |
| `REFORGED` | `OPTIM` + `FIX_MOUSE`. |
| `SKIP_INTRO` | Skips the Atari intro and the logos. |

`--reforged` also adds the asset overlay `mods/reforged/`: an "AI REFORGED 2026" banner on the title screen, generated by `python mods/title/make.py`. The `assets/` folder stays the original one, so `--check` always gives back the exact original.

Tested on a **Mega STe** (8 and 16 MHz): the rebuilt and optimised versions work. The `reforged` version gives noticeably smoother animations, and the mouse is back on when quitting the game.

Gains measured in Hatari on the 4-AI demo, about 12,600 game VBL per measurement:

| Machine | Original | `OPTIM` |
|---|---|---|
| STE | 16.5 frames/s, 19 % of frames at 25 fps | **22.4 frames/s (+36 %)**, 81 % at 25 fps |
| STF | 18.0 frames/s | **18.9 frames/s (+5 %)**, no blitter: original CPU code |

The optimised routines are proven equivalent to the original ones by `tools/difftest.py`, which runs them side by side in a 68000 emulator (see METHODOLOGY.md, §8).

Copy `out/CHUCHU.TOS` and `out/CHUCHU.LNK` into the same folder, on a floppy, a hard disk or Hatari's GEMDOS folder. The executable is not packed: it is 117 KB instead of 65 KB, which changes nothing to how it works.

## Modifying

**The rules of the game.** `src/settings.s` gathers the values that can be changed without touching the code: mouse and cat speeds, spawn delays, gold and purple mouse frequency, number of cats during "Cat Mania", arrows per player, arrow lifetime, points scored, roulette event durations, round durations, computer player speed, default options and the choices of the OPTIONS menu (values and texts). Every value is explained in the file; the assembly stops with a message when a value is out of range. With the shipped values, you always get the original game, identical to the byte.

Two remarks: the menu options are saved in `CHUCHU.SAV`, which wins over the `DEFAULT_*` values (delete it to see them); and with a demo round shorter than the demo itself, the demo stays stuck on the end-of-round "Winner!" screen (this is how the original code behaves, not the setting).

**The code.** Edit `src/chuchu.s` directly. Everything that is an address is a label, so instructions can be added or removed anywhere. Two rules:
- a short branch (`bra.s`, `bne.s`…) reaches ±128 bytes: change it to `.w` when it no longer reaches its target (vasm tells you);
- vasm runs with `-no-opt` to stay faithful to the byte: it optimises nothing for you.

The demonstration modification `SKIP_INTRO` shows how to proceed, with `ifd`/`ifnd` blocks in `App_FrontEndStateMachine` and `Intro_LogosAndTitle`.

**The graphics.** Edit the PNGs of `assets/` in an editor that respects **indexed PNGs**: GrafX2, Aseprite, Pro Motion, or GIMP in indexed mode. Then run `build.py` again. Modified files are stored unpacked in `CHUCHU.LNK`, which the loader accepts: it only depacks what starts with `ICE!` or `ATM5`.

| Format | PNG | Convention |
|---|---|---|
| `.PI1` (Degas) | 320×200, 16 colours | The PNG palette is the ST palette. It is converted back to 4-bit STE values. |
| `.BSB` (GodLib sprites) | Sprite sheet, side by side + `.json` | Indices 0 to 15 opaque, 16 transparent, 17 to 31 transparent with a leftover colour (rare). |
| `.GFX` (masked image) | Image + `.json` | Same convention as `.BSB`. |

The display palette of the sprites is `BOARD.PAL`, or `ATARIPAL.PAL` for the intro. Only the indices matter.

Example: `python mods/title/make.py` adds a banner on the title screen, written with the game's font (`FONTMID.IMG`). Combined with `-D SKIP_INTRO`, it gives the version shown in `docs/mod_demo.png`.

## Testing in Hatari

`run/run.sh <folder> <vbl_count>` runs the game without a display (STE, 4 MB, EmuTOS) and records an AVI. Left alone, the game switches to **demo mode**, with 4 AI players: an excellent regression test.

The built executables are in `dist/`: `reforged/`, `reforged_sans_blit/` (`--reforged -D NO_BLIT`) and `reconstruit/` (rebuilt, no option).

## Layout

```
src/chuchu.s        the source (master file: this is the one you edit)
src/settings.s      the game settings (speeds, scores, times...)
assets/             the data, graphics as indexed PNGs
orig/               your original files (CHUCHU.TOS, CHUCHU.LNK)
build.py            build
tools/              Pack-Ice depacker, LINKFILE, converters, disassembler, checks,
                    xref / rename / codemap
analysis/           disassembly result (trace.json), recognised names,
                    renames and comments applied to the source (*.map)
mods/               demonstration modifications
run/                Hatari launcher (+ EmuTOS 1.4, GPL)
perf/               profiling and frame-rate measurement in Hatari
docs/               screenshots
METHODOLOGY.md      how all this was obtained and checked
GAME_LOGIC.md       how the game works, and where to find it
CODE_MAP.md         complete map: every function and variable
```

To find your way in the source without reading assembly: `GAME_LOGIC.md`, then `CODE_MAP.md`, then `python tools/xref.py NAME` (who calls what, which variables). `python tools/rename.py FILE.map` renames labels and adds header comments, checks that the executable stays identical, then regenerates `CODE_MAP.md` (`python tools/codemap.py`).

`tools/setup.py` regenerates `src/chuchu.s` and `assets/` from `orig/`, in the raw form of the first disassembly. **It overwrites all the work done on the source** (names, comments, settings, optimisations): it is only useful to start again from scratch. The project is versioned with git: run `git diff` to see what you changed.
